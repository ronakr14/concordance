SHEET 1: OVERVIEW
============================================================

Purpose: AI-powered healthcare provider reconciliation, human approval, and 3-month case management.
Team Size: 4
Recommended Stack: AWS PostgreSQL, Python, FastAPI, Streamlit, RapidFuzz, LLM API, Pandas, SQLAlchemy, Docker, Git

Role Assignments:
- Sachin | Data & Database Engineer | Primary Ownership: Provider master + sanction data + PostgreSQL | Key Deliverable: Database, realistic datasets, sanction Excel, ground truth | Dependencies: Defines data contract with all
- Ronak | AI / Entity Resolution Engineer | Primary Ownership: Hybrid matching + AI reasoning | Key Deliverable: Matching engine, confidence, explanations, ambiguity detection | Dependencies: Provider/sanction schema
- Aditya | Backend & Case Management Engineer | Primary Ownership: APIs + workflow + audit | Key Deliverable: FastAPI, approval/rejection, case creation, audit trail | Dependencies: DB + matching response contract
- Sarang | UI & Analyst Experience Engineer | Primary Ownership: Dashboard + review experience | Key Deliverable: Streamlit dashboard, investigation page, case UI, AI assistant | Dependencies: API contract
- Sarang | Integration Lead | Primary Ownership: Architecture + integration + testing + demo | Key Deliverable: End-to-end integration, acceptance tests, presentation | Dependencies: All four workstreams

Core Flow:
Provider DB + Sanction Excel -> Normalize -> Hybrid Matching -> Explainable Confidence -> Admin Review -> Case Creation -> Audit/Dashboard

Key Differentiators:
Hybrid deterministic + fuzzy + AI matching; explainable AI; ambiguity detection; human-in-the-loop; measurable precision/recall; optional AI analyst assistant


SHEET 2: ROLE 1 - DATA & DATABASE ENGINEER
============================================================

  Details: Create providers, sanction_records, provider_matches, cases, audit_logs tables.

  Deliverable: Messy test data

  Deliverable: Ground-truth dataset

Area: Data Dictionary

  Deliverable: data_dictionary.md

Area: Acceptance Criteria

SHEET 3: ROLE 2 - AI / ENTITY RESOLUTION ENGINEER
============================================================

Objective: Build a hybrid matching engine that combines deterministic rules, fuzzy similarity, and AI reasoning without blindly relying on an LLM.

Stage 1 - Normalization
  Task: Normalization
  Details: Normalize names, addresses, dates, states, punctuation, whitespace and common abbreviations.
  Deliverable: normalization.py

Stage 2 - NPI Validation
  Task: NPI Validation
  Details: Detect NULL, blank, 0000000000, 9999999999, UNKNOWN, N/A and other configured invalid values.
  Deliverable: npi_validator.py

Stage 3 - Exact Match
  Task: Exact Match
  Details: Use valid NPI for deterministic matching; flag conflicting attributes for review.
  Deliverable: Exact match logic

Stage 4 - Candidate Generation
  Task: Candidate Generation
  Details: Reduce provider population using state, DOB, name similarity, license and other available attributes.
  Deliverable: candidate_generator.py

Stage 5 - Fuzzy Matching
  Task: Fuzzy Matching
  Details: Use RapidFuzz for name/address similarity and field-level scores.
  Deliverable: fuzzy_matcher.py

Stage 6 - Weighted Scoring
  Task: Weighted Scoring
  Details: Combine name, DOB, address, license and state scores using configurable weights.
  Deliverable: scorer.py

Stage 7 - AI Resolution
  Task: AI Resolution
  Details: Send only ambiguous/top candidates to LLM. Ask it to select a candidate or declare ambiguity.
  Deliverable: ai_matcher.py

Stage 8 - Structured Output
  Task: Structured Output
  Details: Return decision, provider_id, confidence, field scores and evidence as JSON.
  Deliverable: Match response contract

Stage 9 - Explainability
  Task: Explainability
  Details: Show why the match was selected using only supplied evidence.
  Deliverable: AI explanation

Stage 10 - Ambiguity
  Task: Ambiguity
  Details: Allow AI to return NO_CONFIDENT_MATCH / AMBIGUOUS instead of forcing a match.
  Deliverable: Safe fallback

Stage 11 - Evaluation
  Task: Evaluation
  Details: Compare predictions against ground truth; calculate precision, recall, F1 and false positives.
  Deliverable: Evaluation report

Stage 12 - Prompt Safety
  Task: Prompt Safety
  Details: Explicitly prohibit inventing facts or determining misconduct; focus only on entity resolution.
  Deliverable: Versioned prompt
